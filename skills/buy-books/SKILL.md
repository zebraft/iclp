## 一般研究者薦購執行規則 / Standard researcher-run defaults

A request such as “buy-books: [Drive booklist] for [researcher]” is sufficient to start a new researcher recommendation issue. Do not require colleagues to repeat the workflow, destination, privacy rules or output format in each prompt. Apply these defaults unless the user explicitly changes them:

1. Use the supplied Drive booklist as the source and the named researcher's verified live institutional profile plus registered acquisition preferences as the interest answer. Do not ask them to repeat those interests. Never invent a profile or recipient identity. Ask only for essential information that connected sources cannot resolve.
2. Prepare up to 10 relevant titles for the initial/pilot issue when no count is specified. Do not pad with weak matches. An explicit count, full-list instruction or enabled service configuration takes precedence. This limit never applies to holdings-only screening.
3. Call `recommendation_delivery_status` and use its private `staffWorkbookUrl` as the permanent service register. Reuse that workbook across source booklists; append a new issue and preserve previous issues, numbering, decisions, source-row mappings and the deduplicated Buyer queue. Store AI candidate records in hidden tabs named `AI candidates - [researcher]`. Keep `採購清單 Buyer queue` first and visible, labelled as confirmed recommendations. Never present the full candidate tab as a purchasing list. Do not ask for the workbook URL again, create a new destination per booklist, or use the ad hoc output-folder workflow for this service. If configuration or access is missing, state that specific blocker rather than silently choosing another workbook.
4. Read the complete relevant source pool, select against the verified profile, check AS holdings under this skill's evidence rules, exclude confirmed holdings/orders and flag unresolved results. Save private staff rationale, profile snapshots and bibliographic provenance in the staff register.
5. Create the personal 挑書 confirmation link through `create_recommendation_checklist` as part of this default run, using the new immutable registered issue and canonical workbook. The issue remains a draft unless actual email delivery is authorized and verified. Use the returned frontend link, never an invented URL.
6. Keep researcher names, registered emails, research profiles, personalized rationales, staff issue labels, previous private comments, internal Drive links and staff receipts out of the researcher-facing webpage/API and public source examples. Those records remain in private staff storage. Bibliographic author names are book metadata. Keep the personal capability link private; a visit is not consent and no response is not a selection.
7. Verify automatic writing from the live delivery status. Submissions save durably before workbook delivery; a successful receipt requires readback. The Apps Script trigger handles bounded pending-response recovery. Do not ask the colleague to poll or synchronize each submission manually. Agent reconciliation is recovery only.
8. Return the private staff workbook link, personal confirmation link, input/selected/excluded/unresolved counts and any actual blockers. Keep the result concise; do not make the user reconstruct configuration from procedural notes.
9. A source-and-name request authorizes preparation, holdings checks, staff-register updates and checklist creation. It does not by itself authorize email sends, purchaser notifications or orders. Sending still needs explicit applicable service/session authorization, a verified official sender and recipient. Never carry an unrelated test's sending permission into a colleague's run. Do not place orders.

These researcher-service defaults take precedence over the generic ad hoc export and folder rules below. An explicitly authorized end-to-end email run must still be completed under its authorization rather than silently downgraded to draft-only work.

## Check AS holdings in batches

1. Prefer the connected **院內館藏查核 AS Holdings Checker** for WorldCat Search API checks. Read [API holdings workflow](references/holdings-api.md) before the first call; check `worldcat_connection_status`, then call `check_as_holdings` with at most three books per request. Preserve source-row mappings and reconcile every returned record. The following Discovery browser rules are a fallback or supplementary check, not mandatory browser steps for API calls. If the checker is unavailable or cannot resolve scope, orders, identity or volume holdings, use https://aslib.on.worldcat.org through the authorized browser workflow when available. Read current browser guidance first, follow site safeguards, and never promise unattended browser access.
2. Use `scripts/catalog_batches.py` with JSON rows containing unique `id` and `title` fields to generate encoded `ti:("TITLE A") OR ti:("TITLE B")` queries and a row-to-batch manifest. It generates links only, not holdings evidence. Start with at most 10 titles and reduce for query/URL limits or ambiguity. ISBN OR batches may supplement title searches, but must not replace bibliographic reconciliation.
3. Do not equate 40 words with 40 titles. OCLC documents a query-word limit with special phrase counting: https://help.oclc.org/Discovery_and_Reference/WorldCat_Discovery/Search_in_WorldCat_Discovery/010Search_and_use_query_syntax . A 10-title batch is a starting point, not a guaranteed supported size.
4. Verify visibly that “中央研究院 / Academia Sinica” is selected and “Libraries Worldwide” is unselected for each search. `databaseList=638`, `clusterResults=false` and `groupVariantRecords=false` alone do not establish local scope.
5. Wait for the submitted query's results to finish rendering before reading them. A changed search-box value/URL with the previous count or a loading skeleton is not evidence. Check pagination and inspect all relevant result pages. Never match input titles merely by total result count; related-term expansion, contents and series fields can produce false positives.
6. Reconcile each input against title, responsible author/editor/translator, ISBN, publisher, year, edition and format. For misses, run individual ISBN and shortened title/author variants, including Chinese script and punctuation differences. A single exact-phrase miss is insufficient for `no`. Check issue/volume-level holdings and standing-order evidence for continuing series; another issue does not establish ownership of the requested one.
7. Use **title-level duplicate screening by default**: a confirmed AS holding or order for the same work, including an earlier edition, counts as already represented and is excluded. Record edition differences explicitly. Respect an explicit same-edition-only request. Do not equate distinct works, critical editions or translations solely from a shared short title; if identity is unclear, retain as `uncertain`.
8. Set the exact column `AS holding?` only to:
   - Leave it blank before an attempted check and use a separate `Check state` value `not checked`; never report an unattempted check as `uncertain`. Every delivered screened row must have an attempted check and one of the three statuses below.
   - `yes`: explicit AS holding/order evidence for the same work under the selected matching rule. Record available, checked out, on order or processing separately; an order is not an on-shelf copy.
   - `no`: completed AS-scoped batch and individual follow-ups found no matching holding/order under that rule. Record a dated catalog non-match, not an absolute claim of absence.
   - `uncertain`: blocked/failed/incomplete search, unverified scope, ambiguous work/edition identity, unresolved issue holdings, conflicting metadata, or only “Not Available” without sufficient holding/order detail. Keep the entry; do not describe it as confirmed unheld. For researcher-recommendation pilots, it may still be offered as a candidate with a clear holdings-review flag; the buyer must recheck it before handoff or purchase.
9. A wrong ISBN that resolves to another title does not establish holdings of the requested title. Preserve the supplied ISBN, record the matched ISBN separately, and flag the discrepancy. If title/author evidence independently confirms the same work is held/ordered, record that basis and the discrepancy instead of blindly treating the ISBN miss as `no`.
10. Save per-row status, short evidence, exact observed catalog URL, matched edition/location and Asia/Taipei check date after each batch. Keep pending IDs. Label generated unvisited links as unverified; do not present them as observed evidence. Never infer ownership from worldwide results or a researcher publication list.
11. If blocked, preserve completed work and mark affected rows `uncertain`, offering batch links for manual review. Do not work around site controls or report technical failure as `no`.
